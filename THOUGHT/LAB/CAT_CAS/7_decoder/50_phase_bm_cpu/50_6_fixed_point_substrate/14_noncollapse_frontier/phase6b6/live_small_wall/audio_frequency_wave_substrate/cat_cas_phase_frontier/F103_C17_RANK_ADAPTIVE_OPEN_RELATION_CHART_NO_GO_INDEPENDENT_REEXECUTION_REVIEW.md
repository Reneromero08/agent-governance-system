## Reconstructed mechanism

The production path represents a non-translation-invariant `C17 -> C17`
relation by an exact canonical rank chart. A rank-`r` chart has
`r(34-r)` field-value coordinates plus deterministic pivot metadata. Native
left composition by `I + lambda U V^T` with rank-two `U V^T` preserves the
target rank. Parallel Hadamard intersection with the declared structured
rank-two control can grow rank, and its entrywise reciprocal is also rank two,
so the same actual control supports exact forward and inverse execution.

The independent oracle imports neither production nor NumPy. It reconstructs
the public programs, structured controls and reciprocals, nonsingular
couplings, dense relation semantics, rotations, composition, intersection,
final boundaries, exact ranks, reverse order, and semantic mutations in plain
Python modular arithmetic.

## Observed result

All 18 cases over three public families and depths `1, 2, 4, 8, 32, 128`
match the independent dense recurrence. The oracle makes 531 explicit
comparisons. Rank grows from two to as high as four after depth one, eight
after depth two, 13--16 after depth four, and 17 by depth eight; every target
has exact rank 17 by depth 32 in all three families.

At rank 17 the canonical left pivot factor is identity, so the 289-cell
resident payload is the relation transpose. The implementation does not
retain a second dense table, but the accepted chart is explicitly
dense-equivalent at that ceiling. This is not sub-dense fixed-rank closure.

The production carrier retains 3,375 bytes: 612 resident control-factor
coordinates, 2,601 target payload coordinates, 153 pivot bytes, and nine rank
bytes. The executed rematerialized-control classical hybrid uses the same
chart only through rank eight and then switches to a 289-cell dense target;
its maximum resident total is 2,672 bytes. The conservative named warm maxima
are 44,269 bytes for the phase path and 35,950 bytes for the classical path.
Python-container, allocator, NumPy/native-library internal, and whole-process
peaks remain excluded and no optimal classical implementation is claimed.

The complete inverse acts on the actual resident payload. Full-rank execution
is followed by one exact, history-free factor canonicalization, restoring the
unique canonical machine representation. Every carrier byte and backing
identity restores exactly without snapshot, retained inverse history, or
baseline reload. An unrelated depth-37 program reuses the same carrier after
depth seven, and 32 repeated depth-four transactions restore exactly.

## Controls

The production and/or independent oracle distinguish missing inverse, wrong
inverse, reordered inverse, null port, composition/intersection order,
topology mutation, premature projection, resident-port projection, wrong
type, wrong owner, and null carrier. All 2,601 structured-control entries have
an exact rank-two reciprocal certificate. Public topology compilation does not
read final answers.

## Claim ceiling

The result is limited to exact `F103` non-translation-invariant `C17 -> C17`
relations reached by the declared reciprocal-rank-two controls on the public
nine-node rotating-hub topology, across the 18 cases through depth 128 in
Linux direct-process software.

It establishes neither sub-dense closure after rank saturation, increasing
interface cardinality, arbitrary topology, CATVM custody, a distinct phase
resource, computational advantage, Small Wall crossing, physical waveform or
silicon execution, replacement of physical bits with pi, nor unbounded
catalytic computation.
